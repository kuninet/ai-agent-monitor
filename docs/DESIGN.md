# 設計

AI Agent Monitor が何を読み、どう数えているかをまとめます。どちらのツールも会話記録の形式を公開していないため、ここに書いた解釈は実データの観察に基づいています。

## 構成

```
src/
  server.js            HTTP サーバーと CLI
  aggregate.js         期間・エージェントで絞り込み、画面用の JSON を組み立てる
  collectors/claude.js Claude Code のデータ収集
  collectors/agy.js    Antigravity CLI のデータ収集
  collectors/codex.js  Codex のデータ収集
  agents.js            エージェントの一覧(表示名・データの場所・収集処理)
  config.js            監視するエージェントの設定の読み書き
  jsonl.js             追記型 JSONL の差分読み込み
  pricing.js           Claude API の単価表と費用計算
  proc.js              プロセス情報(ps)と Orca CLI の呼び出し
public/
  index.html           画面(単一ファイル、外部リソースなし)
```

依存パッケージはありません。agy の会話一覧と Codex のスレッド一覧(どちらも SQLite)は `node:sqlite` で読み取り専用に開きます。

## 読み込みの方式

会話記録は追記型の JSONL です。ファイルごとに読み込み位置と集計途中の状態を保持し、2 回目以降は追記された分だけを読みます。

- 追記分は 8MB ずつ読み、改行で終わる行だけを処理します。書きかけの最終行は次回に持ち越します
- ファイルが縮んだとき、または inode が変わったときは、先頭から読み直します
- 壊れた行は読み飛ばします
- 一覧から消えたファイルのキャッシュは削除します

同じサイズのまま内容が書き換えられた場合は検知できません。どちらのツールも追記しかしないので、実害はありません。

## セッションの状態

| 状態 | 表示 | 意味 |
|---|---|---|
| running | ● 実行中 | エージェントが作業している |
| question | ? 質問待ち | 選択式の質問に人の回答を待っている |
| waiting | ○ 入力待ち | プロセスは生きていて、次の指示を待っている |
| ended | – 終了 | プロセスが無い |

### Claude Code

`~/.claude/sessions/<pid>.json` と実際のプロセスで判定します。pid が生きていて、ファイルの開始時刻と `ps` の開始時刻が一致するものを生きているとみなします(pid の再利用対策)。

1. 生きていて、回答の付いていない `AskUserQuestion` がある → question
2. 生きていて、status が busy → running
3. 生きている → waiting
4. 生きていないが、90 秒以内に更新がある → running
5. それ以外 → ended

### Antigravity CLI

`--conversation <id>` 付きで起動している agy プロセスは、その会話を動かしているとみなします。

`agy -c` や引数なしで起動した agy は、コマンドラインから会話が分からないので、statusline の保存ファイル(`~/.ai-status/agy/<conversationId>.json`)と対応づけます。agy は入力待ちの間は statusline を呼ばないので、「最近保存された」ことではなく、プロセスの開始時刻との前後で判定します。

1. 候補は、そのプロセスの開始以降に保存された会話です。開始時刻が取れない場合は、10 分以内に保存された会話です
2. `--conversation` のプロセスが動かしている会話と、ダッシュボードが過去 24 時間に `--conversation` のプロセスとして見た会話(その後に新しい保存が無いもの)は、候補から除きます
3. macOS と Linux では、プロセスの作業ディレクトリと、保存ファイルに記録された作業ディレクトリが一致する会話だけを候補にします(macOS は `lsof`、Linux は `/proc/<pid>/cwd`)
4. 候補のうち最も新しく保存された会話を、そのプロセスの会話とします。ただし、その会話が 2 つ以上のプロセスの候補になっているときは、どちらにも割り当てません(取り違えて「動作中」と出すより、出さない方を選びます)

どちらで判定したかは、API の `sessions[].liveBy`(`arg` または `statusline`)で分かります。

同じ作業ディレクトリで `--conversation` 付きの agy と会話 ID なしの agy を並べて使い、その間ダッシュボードが止まっていた場合は、終わった会話を会話 ID なしの agy のものと取り違えることがあります。Windows ではプロセスの作業ディレクトリが取れないので、3 の絞り込みは行いません。

1. 生きていて、未回答の `ask_question` がある → question
2. 生きていて、会話一覧の status が RUNNING、または会話記録が 60 秒以内に更新されている → running
3. 生きている → waiting
4. 生きていないが、90 秒以内に更新がある → running
5. それ以外 → ended

### Codex

1 つの app-server プロセスが複数の会話を扱うため、プロセスと会話を対応づけられません。会話記録のターンの開始・完了のイベントと更新時刻から推定します。

1. 完了していないターンがあり、回答の無い `request_user_input` がある → question
2. 完了していないターンがあり、10 分以内に更新がある → running
3. ターンが完了していて、`codex` プロセスが動いていて、30 分以内に更新がある → waiting
4. それ以外 → ended

承認の判定に使われる guardian スレッドは表示しません。タイトル欄に会話記録や設定ファイルの内容がそのまま入っているためです。

## KPI の定義

KPI は、選んだ期間に起きたイベントだけで集計します。セッションが期間より前に始まっていても、期間内の分だけを数えます。

### API 換算額

Claude のみです。会話記録に残る各応答の usage に、Claude API の公開単価を掛けて合計します。

- cache write は、5 分 TTL を入力単価の 1.25 倍、1 時間 TTL を 2 倍で計算します
- cache read の単価はモデルごとに違います
- fast mode は 2 倍にします
- 単価表に無いモデルは費用に含めず、そのモデル名を別に返します

ストリーミング中の応答は、同じ message.id で複数の行に分けて記録されます。usage は `stop_reason` が確定した行の値を採り、確定した行が無ければ output_tokens が最大の行の値を採ります。途中の値のまま残っている応答もあるため、換算額は実際より少なめに出ることがあります。

表示中の期間とは別に、当月 1 日からの Claude の換算額を `kpis.monthToDate` に出します。プランの月額(`claudePlanMonthlyUSD`)が設定されていれば、月額との比も出します(未設定なら比は null)。当月分に単価表に無いモデルがあれば、そのモデル名も返します。

Codex と agy は定額制なので換算額を出しません。

### キャッシュ読込率

`cacheRead ÷ (input + cacheRead + cacheWrite)` です。全体の値は Claude と Codex で計算し、agy はエージェント別の値としてだけ出します。Codex は `token_count` イベントの `cached_input_tokens ÷ input_tokens` です。同じ値の `token_count` が繰り返し記録されるので、累計が増えたときだけ数えます。agy は、statusline から取れる直近 1 回分のリクエストの値を使います。

### ツールエラー率

`エラー数 ÷ ツール呼び出し数` です。許可の拒否とユーザーによる中断は、分母にも分子にも入れません。

- Claude: `tool_result` の `is_error` をエラーとします
- Codex: ツール呼び出しの出力に、0 以外の終了コードや失敗メッセージがあればエラーとします。サンドボックスによる拒否はエラーに数えます。ユーザーによる拒否と中断は除きます
- agy: 応答に含まれるツール呼び出しと、それを実行するステップを順番に対応づけ、ステップの status が ERROR のものをエラーとします。実行中のまま記録が止まるステップがあるため、エラー数は下限値です

### 文脈の読み落とし

コンテキストの圧縮回数です。

- Claude: `compact_boundary` の回数と、圧縮で捨てたトークン数(`preTokens - postTokens`)
- Codex: `compacted` の回数(捨てたトークン数は取れません)
- agy: CHECKPOINT ステップの回数(捨てたトークン数は取れません)

### 自動続行

人の入力以外から始まったターンの数です。

- Claude: `origin.kind` が human 以外のユーザー行(バックグラウンドタスクの完了通知など)と、チームのメンバーからの報告(「Another Claude session sent a message:」で始まる行)
- Codex: ユーザーの発言が無いまま始まったターン(サブエージェントの報告を受けて続いたターンなど)
- agy: SYSTEM_MESSAGE ステップと、人以外が起点の USER_INPUT

### タスク

- Claude: `TaskCreate` と `TaskUpdate` を、ツールの結果が返った時点で反映します。エラーで返った場合は反映しません。`~/.claude/tasks/` に現在値があれば、それで上書きします。古い形式の `TodoWrite` にも対応しています
- Codex: `update_plan` で最後に出したプラン
- agy: 会話ごとの `task.md` のチェックリスト(`[ ]` 未着手、`[/]` 進行中、`[x]` 完了)です。ID はインデントの階層から `1.2` のように付けます

Blocker は、blockedBy のうち完了していないタスクだけを出します。KPI の未完・進行中・ブロック数は、終了していないセッションのタスクだけで数えます。

### 未回答の質問

- 選択式: Claude は回答の付いていない `AskUserQuestion`、Codex は出力の返っていない `request_user_input`、agy は後に回答の記録が無い `ask_question`
- 文中: ターンを終えて人の入力を待っている応答の本文から、質問や依頼を検出したもの(下記)

終了したセッションの質問は出しません。人が発話すると、答えたかどうかに関係なく未回答から外します。チームのメンバーからの報告や自動のターンは、人の発話には数えません。

#### 本文中の質問の検出

選択式の質問ツールを使わず、本文で「どちらにしますか。」「よければ進めます」のように聞いている応答を拾います。対象は、ターンを終えた最後の応答です(Claude は最後のツール呼び出しより後の本文、Codex は `task_complete` の最後のメッセージ、agy はツール呼び出しの無い最後の応答)。

1. 前処理: NFKC で正規化し、コードブロック、インラインコード、URL、見出し・引用・表の行、括弧の中の引用や「?」を判定から外します。末尾の「Sources:」やリンクだけの段落も捨てます
2. 末尾の 2 段落の各文について、次のどれかに当たるかを見ます
   - 「?」で終わる文、「〜ますか。」「〜でしょうか。」のような文末
   - 条件付きの許可(「〜てよければ〜します」)や依頼の言い回し(「決めてください」「〜もらえれば」)
   - 英語の "Should I" "Would you like" "Do you want"
3. 「必要なら」「気になる点があれば」のような結びの文は数えません。ただし、同じ文で選択を求めているものは残します

「?」や「〜か。」で終わる文、条件付きの許可、選択を求める語に当たったものを「文中の質問」、依頼の言い回しにだけ当たったものを「確認待ち」として分けて表示します。KPI の件数は、選択式と文中の質問の合計で、確認待ちは補足行に出します。文中の質問があるセッションは「質問待ち」の状態になります。

質問の後に番号付きや箇条書きの選択肢があれば、それも表示します。

実際の会話記録約 1,400 件で確かめたところ、質問している応答の約 9 割を拾い、拾ったものの 9 割以上が人の返事や作業を待っている応答でした。

### 作業時間

エージェントが作業していた時間です。人の入力待ちや放置の時間は含めません。作業していた区間を集め、表示中の期間と重なる部分だけを合計します。

- Claude: ターンごとの所要時間(`turn_duration`)があればそれを使います。記録の無いターン(実データでは約 7 割)は、ターン内の行の時刻を並べ、間隔が 2 分以下の部分をつないで区間にします。ツールの呼び出しから結果が返るまでは、2 分を超えていても作業中とみなします(最大 60 分)。ただし、`AskUserQuestion` など人の操作を待つツールは除きます
- Codex: ターンの開始から完了または中断までです。ターンの途中で記録が 30 分を超えて途切れた間と、`request_user_input` の回答待ちは除きます
- agy: 入力から、次の入力の直前のステップまでです。Codex と同じく、30 分を超える空白と `ask_question` の回答待ちは除きます
- 実行中のターンは、現在時刻までを数えます

人の発話やチームのメンバーからの報告は、次のターンの始まりとして扱い、前のターンには含めません。サブエージェントの作業時間は、親と並行して動くので親には足さず、サブエージェントの行に別に出します。

承認の記録は会話記録に残らないため、30 分未満の承認待ちは作業時間に含まれます。

## 使用枠とコンテキスト

- Claude: statusline の入力を `~/.ai-status/claude/<sessionId>.json` に保存してもらい、そこから読みます。使用枠はアカウント共通なので、最も新しいファイルの値を使います。コンテキスト使用率はセッションごとの値を使い、保存が無いセッションは最後の応答の入力トークン数から計算します
- Codex: 会話記録の `token_count` に含まれる `rate_limits` を使います。`window_minutes` が 300 なら 5 時間枠、10080 なら週次枠です
- agy: statusline の入力を `src/statusline-save.js --agy` で `~/.ai-status/agy/<conversationId>.json` に保存してもらい、そこから読みます。自作の statusline スクリプトが書く `last_statusline_input.json` があれば、収集のたびに同じ場所へ会話ごとに写します(保存済みの方が新しければ写しません)。使用枠はアカウント共通なので、`last_statusline_input.json` と保存済みファイルのうち最も新しい入力(`capturedAt`、無ければ更新時刻)の値を使います。コンテキスト使用率とモデル名は会話ごとの保存から読みます
- リセット時刻を過ぎた枠は、古いデータとして表示します

## サブエージェント

### Claude Code

`<sessionId>/subagents/agent-<id>.jsonl` と、同じ名前の `.meta.json` を読みます。

親の履歴をコピーして始まるサブエージェント(フォーク)があるため、同じ message.id や tool_use id が複数のファイルに現れます。そこで、親 → 通常のサブエージェント → フォークの順に走査し、同じ id は最初に現れたファイルの分として数えます。こうすると、各サブエージェントの費用と親自身の分を足した額が、セッション全体の費用と一致します。

状態は、次の順で判定します。

1. 最終行が SubagentStop フック → 完了
2. 最終行が TeammateIdle フック → 待機
3. チームメイト以外で、親の会話記録を見ると、起動したツール呼び出し(`meta.toolUseId`)に結果が返っている → 完了
4. 最後の応答が `end_turn` で終わり、その後にユーザー行が無い → チームメイトなら待機、それ以外は完了。`stop_reason` が記録されず tool_use も無い場合は、45 秒以上更新が無いときだけ同じ扱いにします(応答の生成途中を完了と誤判定しないため)
5. 10 分以内に更新がある → 動作中
6. それ以外 → 中断

親セッションが終了している場合は、動作中を中断に、待機を完了に読み替えます。

### Antigravity CLI

会話一覧で `parent_conversation_id` を持つ会話を子として、最上位の会話の下にまとめます。子の指標は親に合算します。親が表示されない場合、子は独立したセッションとして表示します。

### Codex

スレッド一覧の `thread_spawn_edges`(無ければ会話記録の `parent_thread_id`)で親子を判断し、最上位の会話の下にまとめます。フォークした子の会話記録には、先頭に親の履歴(ツール呼び出し、token_count、ターンの開始・完了、圧縮)がコピーされています。親と子を合わせて、同じツール呼び出し(call_id)、同じ累計トークン、同じターン(turn_id)、同じ圧縮は、最初に現れたファイルの分として 1 回だけ数えます。

### 期間との関係

完了・中断したサブエージェントのうち、最後の更新が期間より前のものは表示しません。動作中と待機中のものは、期間に関係なく表示します。

## 端末への切り替え

Orca の端末タブへ切り替えます。

1. セッションのプロセスの環境変数から `ORCA_PANE_KEY` を読みます
2. `orca terminal list --json` の `tabId:leafId` と照合して、端末の handle を求めます
3. `orca terminal switch --terminal <handle>` を実行します

pane key が取れない場合は、作業ディレクトリとエージェントの種類が一致する端末が 1 つだけのときに限り、その端末を使います。

## 監視するエージェントの設定

`~/.ai-status/config.json` に `{"agents": ["claude", "codex"], "claudePlanMonthlyUSD": 100}` の形で保存します。`claudePlanMonthlyUSD` は Claude のプランの月額(USD)で、無ければ月額との比較を出しません。ファイルが無いか壊れているときは、ログのディレクトリがあるエージェントをすべて監視します。起動オプション `--agents` を指定したときはそちらを使い、画面からエージェントを変更することはできません(月額は変更できます)。

外したエージェントは収集処理そのものを呼びません。

## API

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/` | 画面 |
| GET | `/api/snapshot?range=&agent=` | 集計結果(JSON) |
| GET | `/api/config` | 監視するエージェントの設定と、選べるエージェントの一覧 |
| POST | `/api/config` | 本文 `{agents?, claudePlanMonthlyUSD?}`。指定した項目だけを保存する |
| POST | `/api/jump` | 本文 `{agent, id}`。端末タブに切り替える |

POST の本文は 16KB までです。`/api/jump` は handle やコマンドをクライアントから受け取らず、サーバー側で解決します。Host と Origin が `127.0.0.1` / `localhost` の自分のポート以外のリクエストは拒否します。

`/api/snapshot` のレスポンスの形は `src/aggregate.js` の `buildSnapshot` を参照してください。割合のうち `pct` は 0〜100、`rate` は 0〜1 です。

## 画面の例の撮り方

`docs/screenshot.png` は、`?mock=1` の架空のデータで撮ります。幅 900px 以上かつ高さ 700px 以上の画面では、ヘッダとサブスク枠が固定されてページ全体が伸びないので、ページ全体を撮るときは高さを 700px 未満(例: 1280×690)にしてから撮ってください。
